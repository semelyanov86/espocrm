# Миграция CRM ИТ Волга: Vtiger 7.1 → EspoCRM

Репозиторий переноса CRM `serv.itvolga.com` с Vtiger 7.1 (SalesPlatform) на EspoCRM без платных расширений. Здесь живут аудит источника, карта полей и связей, решения, а на следующих этапах — собственный код EspoCRM (финансы, печатные формы, телефония), импорт, тесты и развёртывание.

**Текущее состояние:** завершён этап 01 — аудит источника. EspoCRM ещё не установлена, production не менялся. Подробности — `TASKS.md`.

## Для пользователя

### Что изменится

После переноса те же данные будут в EspoCRM:

| Было в Vtiger | Станет в EspoCRM |
|---|---|
| Контрагенты, поставщики | Организации (Account), у поставщиков тип «Vendor» |
| Контакты | Контакты; доступы AnyDesk/хост/IP — в отдельной защищённой карточке «Доступ» |
| Обращения (лиды), сделки | Лиды (Lead), сделки (Opportunity) |
| Календарь: задачи, звонки, встречи | Задачи, звонки, встречи |
| Заявки, база знаний | Обращения (Case), статьи базы знаний |
| Документы и файлы | Документы с теми же файлами и папкой |
| Предложения, заказы, счета, акты, платежи | Собственные модули с теми же номерами, датами, суммами и статусами |
| История звонков PBXManager | Звонки (без записей — старые записи были на выведенном сервере) |
| Проекты и задачи проектов | Архивные проекты и задачи (только чтение) |
| Чаты Jivosite, накладная, активы, сервисный контракт | Архив Vtiger (только чтение) |

Что **не** переносится и почему — `docs/migration/module-decisions.md`. Вопросы, на которые нужен ваш ответ (печатные формы, распределение спорных платежей, налоги, роли), — `docs/migration/open-questions.md`.

### Важные факты об исходных данных

- Используется одно юрлицо: значения «Default» и «По умолчанию» — это одно и то же.
- История звонков с 31.07.2024 по 12.06.2026 не сохранилась ни в одном доступном источнике.
- Записи разговоров есть только с 13.06.2026; сейчас они не входят в резервное копирование.
- Пароли AnyDesk сейчас видны всем, у кого есть доступ к контактам, и хранятся открытым текстом; в EspoCRM они будут доступны только отдельной роли.

## Для разработчика

### Структура

```
AGENTS.md                 правила проекта для агентов/сессий (читать первым)
TASKS.md                  состояние этапов, блокеры, стартовая команда следующей сессии
docs/migration/
  source-inventory.md     инвентаризация источника (модули, поля, статусы, ACL, файлы, логика)
  field-map.csv           каждая колонка каждой непустой таблицы → цель, преобразование, сверка, судьба
  relations.csv           все связи: поля-ссылки, M:N, строки документов, распределение платежей
  module-decisions.md     судьба каждого непустого модуля
  finance-contract.md     фактический финансовый контракт (суммы, налоги, нумерация, платежи)
  telephony-sources.md    PBXManager, CDR MySQL/CSV, WAV, AMI, пропуски истории
  print-forms.md          печатные формы и шаблоны
  decisions.md            журнал решений (D-xx)
  open-questions.md       открытые вопросы (Q-xx)
  evidence.md             время, источники, воспроизводимые запросы
scripts/
  audit/                  воспроизводимый read-only аудит источника
    run-audit.sh          полный прогон (~30 с), результат — в приватный каталог
    lib.sh                общие функции (READ ONLY SQL по SSH)
    sql/*.sql             запросы (только агрегаты/метаданные; 50_* — вход для хеширования ПДн на сервере)
    remote/*              скрипты, исполняемые на сервере; наружу — только счётчики/хеши
    gen_sql.py            генерация SQL счётчиков по метаданным схемы
    consolidate.py        сводная таблица колонок (приватно)
    mapping.py            правила маппинга Vtiger → EspoCRM (предложения этапа 01)
    build_maps.py         генерация field-map.csv и relations.csv
    build-pii-hashes.sh   приватный список sha256 реальных ПДн для проверки Git
  check-secrets.sh        проверка секретов/ПДн перед коммитом (--history, --self-test)
  check-secrets.allow     обоснованные исключения проверки
```

### Требования

- Linux, `bash`, `python3` (≥ 3.10), `ssh` с ключом к `sergey@serv.sergeyem.ru` и `sudo -n` на сервере (используется только для чтения).
- Приватный каталог `/data/itvolga/espo-private/` (создаётся скриптами, права 700).

### Повторить аудит

```bash
scripts/audit/run-audit.sh                          # новый приватный каталог с меткой времени
AUDIT_TS=20260929T1840 scripts/audit/run-audit.sh   # перезаписать указанный
scripts/audit/build-pii-hashes.sh                   # обновить хеши ПДн для проверки Git
```

Скрипт перегенерирует `docs/migration/field-map.csv` и `relations.csv`. Правила маппинга меняются в `scripts/audit/mapping.py`, CSV руками не редактируются. Переменные: `AUDIT_HOST`, `AUDIT_DB`, `AUDIT_PRIVATE_ROOT`, `AUDIT_TS`.

### Колонки `field-map.csv`

`source_module, source_table, source_column, source_field, source_label, uitype, source_db_type, custom, nonempty_all_rows` (все строки таблицы, включая удалённые записи), `live_records`, `nonempty_live` (непустые среди живых записей; числа — ненулевые; чекбоксы — «да»; для служебных таблиц без связи с `vtiger_crmentity` эти две колонки пусты — понятие «живая запись» к ним не применимо), `target_entity, target_field, transform, verification` (`count`, `count+hash`, `count+sum`, `count+distribution`, `fk`, `file-hash`), `fate` (перенос / архив / защищённое хранилище / пусто / исключено / категория служебной таблицы), `mapping_status` (**предложено** — цель ещё не реализована и не проверена в EspoCRM; **решено**; **не проверено** — семантика не установлена), `count_status`.

### Правила безопасности

Коротко (полностью — `AGENTS.md`): production только читается; в Git — никаких дампов, строк данных, файлов, аудио, реквизитов и секретов; значения полей доступа контактов не выводятся никуда; перед коммитом — `scripts/check-secrets.sh --history`.
