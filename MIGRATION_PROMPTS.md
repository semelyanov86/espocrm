# Миграция Vtiger → EspoCRM: промпты по этапам

Запускай **один промпт за сессию** в этом репозитории, по порядку. Каждый промпт имеет собственный проверяемый результат и запрещает переходить к следующему этапу в той же сессии. Если этап заблокирован, агент завершает всю независимую работу и фиксирует блокер в `TASKS.md`.

Цель: EspoCRM без платных расширений, с собственным открытым кодом для финансовых документов и телефонии. Код, настройки, модели, шаблоны, скрипты, тесты и Ansible должны быть в Git. Дампы, персональные данные, аудио, реквизиты доступа и приватные отчёты в Git не попадают. До промпта 10 рабочий сервер `sergey@serv.sergeyem.ru` доступен только для чтения. Не использовать как готовый экспорт старые `scripts/export-vtiger.sh`, `task export:vtiger` и `task migrate:vtiger` из `/data/server`: они относятся к прежнему серверу, которого больше нет. Не ставить Sales Pack, VoIP Integration и другие платные пакеты, не копировать их исходный код и схемы.

## Правило передачи между сессиями

Первый этап создаёт постоянную память в Git. **Каждый следующий этап** начинает с чтения `AGENTS.md`, `TASKS.md` и относящихся к нему файлов `docs/migration/`, а заканчивает обновлением этих файлов, проверкой `git diff`/секретов и отдельным коммитом. `TASKS.md` должен содержать: текущий этап, завершённые и незавершённые пункты, блокеры, результаты проверок с датой, путь к приватным отчётам **без их содержимого** и точную стартовую команду для следующей сессии. SHA текущего коммита указывай в итоговом ответе; следующая сессия может проверить его через `git log -1`. При расхождении документов с живым сервером приоритет у свежей read-only проверки; исправление карты и дата проверки обязательны.
