# Решения по модулям

Статус: судьбы модулей **утверждены владельцем 2026-09-29** (`open-questions.md`, «Закрытые»; `decisions.md`). Счётчики проверены SQL (повторно 2026-09-30). **Этап 03 (2026-09-30)** реализовал в EspoCRM все нефинансовые цели этой таблицы — стандартные сущности с кастомными полями, собственные `Vendor`, `Product`, `Project`, `ProjectTask`, `VtigerArchive`, `ContactAccess`, роли и доступ (модуль `custom/Espo/Modules/Itvolga`, описание — `model.md`); каждая цель сверена с моделью (`field-map.csv`/`relations.csv`, колонка `espo_check`). Финансовые сущности — этапы 04.x, телефония — 07.x, импорт данных — 06.x.

Судьбы:
- **Рабочая сущность** — данные импортируются в сущность EspoCRM, с которой работают пользователи.
- **Исторический архив** — данные импортируются только для чтения: в собственную сущность (`Project`, `ProjectTask`) или в `VtigerArchive` (одна запись на исходную запись, поля в JSON + связи + вложения).
- **Исключение** — не импортируется, с обоснованием; исходные данные остаются в защищённом снимке этапа 06.1.

Общие правила для всех модулей:
- Удалённые записи (`deleted=1`, всего 836) в рабочие сущности не переносятся; остаются в защищённом снимке.
- Каждая импортируемая запись получает `vtigerId` (исходный `crmid`) — ключ идемпотентности импорта; исходный номер — `number` (финансы) или `vtigerNo` (остальные).
- Непустые значения без рабочего поля сохраняются в `vtigerData` (JSON, только чтение, видно администраторам) — ни одна непустая колонка не теряется молча.
- Владелец: пользователь → `assignedUser`; группа → `teams` (+ пустой `assignedUser`). Автор/даты — `createdBy/createdAt/modifiedBy/modifiedAt`, если импорт это позволяет.
