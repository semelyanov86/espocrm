# Живая телефония: интеграция EspoCRM ↔ Asterisk (этап 07.1)

Контракт собственной открытой интеграции (без платных расширений EspoCRM). Решения — D-164…D-172 (`decisions.md`),
источники и факты production — `telephony-sources.md`, шаблоны для production — `deploy/production/telephony/`,
тестовая АТС стенда — `deploy/telephony/`. Проверено на изолированной АТС с пакетом Asterisk production
(`1:22.5.2~dfsg+~cs6.15.60671435-1`, Ubuntu 26.04), production только прочитан (2026-10-13).

## 2. AMI: пользователи и права (D-169)

AMI production: `bindaddr=127.0.0.1`, без пользователей, `#include "manager.d/*.conf"` (проверено 2026-10-13). Интеграция
добавляет один файл `manager.d/itvolga-espo.conf` (`deploy/production/telephony/manager.d-itvolga-espo.conf.example`) и
`manager reload` — без рестарта Asterisk, без изменений диалплана и транков.

| Пользователь | read | write | Зачем | Чего не может |
|---|---|---|---|---|
| `itvolga-espo-listener` | `call,dialplan` + расширенные `eventfilter`: только Newchannel, Newstate, DialBegin, DialEnd, BridgeEnter, BridgeLeave, Hangup, NewConnectedLine и VarSet с `Variable` ровно `MIXMONITOR_FILENAME` | `reporting` | события звонков; путь записи (класс dialplan нужен только для VarSet MixMonitor — у `MixMonitorStart` нет имени файла); список каналов `CoreShowChannels` для сверки после перезапуска | Originate, Hangup, Redirect, Command, чтение паролей SIP (класс `system`) |
| `itvolga-espo-dialer` | — (без событий) | `originate` | звонок из CRM | Command, Hangup, список каналов; Originate приложения `System` запрещает сам Asterisk |

Оба — `deny 0.0.0.0/0.0.0.0`, `permit 127.0.0.1/32`. EspoCRM подключается только к `tcp://127.0.0.1:…` или локальному
Unix-сокету (`TelephonyConfig::isLocalAddress`, проверяется и при настройке, и при каждом подключении). Самопроверка —
`task espo -- itvolga-setup-telephony --check` (на стенде входит в `task telephony:up` и в тесты).

## 3. Какие звонки записываются и как (D-164, D-165)

Звонок = все каналы одного Asterisk `linkedid`; ключ `Call.cAsteriskLinkedId` (уникальный). Направление определяет
**первый канал** (`Uniqueid = Linkedid`) по имени endpoint, не по контексту (транковый канал исходящего звонка тоже
создаётся в контексте `call-in`):

| Первый канал | Класс | `Call` |
|---|---|---|
| транк класса `inbound` в входящем контексте (`call-in`) | внешний входящий | сразу, даже если звонящий положил трубку в голосовом меню |
| телефон (`^[12][01][0-9]$`) | ожидание → внешний исходящий, когда набирает транк; внутренний, если сначала набрал телефон | только исходящий |
| телефон с `Uniqueid` `crm-<id>` (Originate из CRM) | звонок из CRM | когда наберёт транк |
| транк тренажёра (`trunk-easybell`, класс `ignored`), Local и прочее | не записывается | — |

Не записываются: внутренние звонки, ящик сообщений (808/908), конференция (811), тренажёр (555/777). Ответ голосового
меню (`Newstate Up` транка) — не ответ человека; ответ — `DialEnd ANSWER` набранного плеча.

| Поле | Значение |
|---|---|
| `status` | `Held`, если ответил человек (телефон, мобильный при переливе, абонент исходящего), иначе `Not Held` — с самого создания (статус «Planned» не используется: ядро создало бы напоминания участникам) |
| `cLiveState` | `ringing` / `talking` во время звонка; `ended`; `lost` — звонок закончился, пока слушатель не работал |
| `direction`, `dateStart`, `dateEnd` | по часам слушателя (в событиях AMI времени нет); во время звонка `dateEnd` — «последний раз видели» |
| `cCallStatusRaw` | итог: `ANSWER`, иначе последний `DialStatus` (`NOANSWER`, `BUSY`, `CANCEL`, `CONGESTION`, `CHANUNAVAIL`), `NODIAL` (не дошло до телефонов), `LOST` |
| `cBillDuration` | секунды разговора: от ответа человека до первого отбоя пары (у истории PBXManager — `billduration`) |
| `cAnsweredAt`, `cExtension`, `cIncomingLine` (DID), `cPhoneNumber` (канонический номер), `cClickToCall` | факты звонка |
| `cRecording` / `cRecordingPath` | признак записи (поле для прав ролей и плеера) / путь относительно корня записей (закрыт для всех через API) |
| `cCdrSource` | пусто у звонков живой интеграции; `mysql`/`csv` — звонок перенесён историей CDR (07.2); живой писатель, записав звонок, очищает его (звонок переходит к живой интеграции) |
| `assignedUser` | входящий: ответивший → первый из звонивших телефонов, у которого есть активный пользователь CRM → пользователь внутреннего номера из настройки «Телефония» (production 108, стенд 119); исходящий — звонящий. Пока звонок идёт, ответственный и его команда следуют звонку |
| `users` | все, у кого звонил телефон, и звонящий (участники видят звонок по правилам роли); прежний автоматический ответственный, не участвовавший в звонке (запасной до первого звонка телефона), убирается; звонившие до перезапуска слушателя остаются (восстанавливаются по карточкам) |
| `teams` | основная команда ответственного |
| `contacts`, `leads`, `parent` | точные совпадения номера; родитель — единственный контрагент (из найденных и основных контрагентов найденных контактов) → единственный контакт → единственный лид без контактов; звонок из CRM — запись, с которой звонили |

«Факты закрыты» (D-168): направление, время, статус, номер, исходный статус, длительность разговора, внутренний номер,
запись и ключ меняет только интеграция (опция сохранения `itvolgaTelephony`). API, форма и массовое обновление их
отбрасывают (`readOnlySaved`, readOnly), ORM-страж `TelephonyFacts` закрывает все остальные пути, включая импорт и
системного пользователя. Название, описание, родитель, контакты, лиды, участники правятся по правам роли. Удалить звонок
телефонии может только администратор; удалённый звонок интеграция не создаёт заново.

## 4. Номер и клиенты (D-167)

Каноническая форма — правила импорта Vtiger (`scripts/import/transforms.py`): 11 цифр с 7/8 → `+7…`, 10 цифр с 3/4/8/9 →
`+7…`, `+` и 7–15 цифр, `00` → `+`, 6 цифр — местный номер `+7 8352 XXXXXX` (как в диалплане `_XXXXXX`). Строки с
несколькими номерами или добавочным («доб.», «ext», «,;/») канонической формы не имеют.

- **Точное совпадение** (до 100 записей; больше — список неполный, родитель не выбирается): `PhoneNumber.numeric` равен одной из форм хранения (`7N`, `8N`, `N` для 10 цифр, шесть цифр для
  местного; для международного — цифры и `00`+цифры) — основные и дополнительные номера контактов, контрагентов, лидов.
- **Возможное:** точных нет, но последние 10 цифр встречаются внутри нестандартной строки; показывается в карточке с
  пометкой «возможно» и к звонку не привязывается.
- Поиск делает слушатель один раз на звонок (без прав); каждому зрителю карточка показывает только то, что он может
  прочитать: клиент без права чтения не виден и не считается, ссылка на звонок — только с правом чтения звонка.

## 5. Карточка звонка (D-170)

Штатный механизм всплывающих уведомлений (`app.popupNotifications.itvolgaCall`, опрос `GET Telephony/cards` раз в 3 с;
WebSocket на стенде выключен). Состояние карточек хранит слушатель (`TelephonyCard`: одна строка на звонок и
пользователя), закрытие — сервер (`POST Telephony/cards/:id/dismiss`; в ядре закрытые карточки сверяются с другим id).

| Кому | Состояния |
|---|---|
| входящий: каждому, у кого сейчас звонит телефон | `ringing` → `closed` (звонок ушёл дальше) или `talking` → `ended` у ответившего |
| исходящий и звонок из CRM: звонящему | `dialing` («поднимите трубку» до набора) → `talking` → `ended`; не поднял трубку — `closed` |

В карточке: направление, номер, состояние, найденные клиенты (с контрагентом контакта, «возможно»), «Открыть звонок»,
«Создать контакт» / «Создать лид» (если видимых точных совпадений нет и есть право создания; номер подставляется).
Закрытая карточка исчезает без звука во всех вкладках; карточка, которую сервер перестал отдавать, исчезает через 20 с
(и вернётся, если сервер снова её отдаст); завершённая хранится 30 мин или до закрытия; закрытая пользователем не
возвращается, пока звонок снова не станет для него активным. Клиенты карточки звонка из CRM обновляются, когда номер
набран; окно «Создать контакт/лид» не закрывается вместе с карточкой.

## 6. Звонок из CRM (D-170)

Клик по номеру в любом поле телефона (`metadata/fields/phone.json` → `itvolga:views/fields/phone`), если телефония
включена и у пользователя есть внутренний номер; с клавишей-модификатором — обычная ссылка `tel:`.
`POST /Telephony/dial {phoneNumber, entityType?, entityId?}`:

1. пользователь — не портал и не API, с правом создания звонков; внутренний номер подходит под шаблон и принадлежит
   только ему (иначе 403 `telephonyNoExtension`);
2. номер переводится в строку, которую принимают шаблоны `phones-out` (`PhoneNumbers::dialString`: `+7…`, местный —
   шесть цифр, другая страна — `0`+код; добавочный, внутренний, несколько номеров — 400 `telephonyNumberRefused`);
3. не чаще раза в 5 с (403 `telephonyRateLimited`), запрос сохраняется (`TelephonyCallIntent`) с записью, если её можно
   читать;
4. `Originate Channel=PJSIP/<свой номер> Context=call-out Exten=<строка> CallerID="<номер>" <номер> Async ChannelId=crm-<id>`.

`CALLERID(num)` остаётся внутренним номером — `sub-ifrussia` выбирает транк так же, как при ручном наборе (проверено на
тестовой АТС: маршрут звонка из CRM и ручного звонка с того же телефона совпадает). Ошибка АТС — 503
`telephonyPbxUnavailable`.

## 7. Записи разговоров (D-171)

- Путь берётся из события `VarSet MIXMONITOR_FILENAME` и хранится относительно каталога записей Asterisk
  (`YYYY/MM/DD/<имя>.wav`); другое не сохраняется. `cRecording` = файл есть после окончания звонка.
- `GET ?entryPoint=itvolgaRecording&id=<Call>` (cookie авторизации, публичных ссылок нет): право чтения звонка **и**
  поля «Запись разговора» (роли могут закрыть поле; при нескольких ролях побеждает разрешение), звонок завершён, путь
  безопасен, файл — обычный, внутри корня записей, без символических ссылок на пути (`realpath`), и **никакой другой
  звонок (в том числе удалённый) не хранит тот же путь**. Иначе 403/404.
- Имя файла `sub-monitor` production — минута и два номера, без идентификатора звонка: второй звонок между теми же
  номерами в ту же минуту перезаписывает файл первого. Путь, который хранят несколько звонков, не принадлежит точно ни
  одному — CRM его не отдаёт никому (внешнее ревью 2026-10-17; уникальное имя — изменение диалплана, Q-54, этап 10).
- `audio/wav`, `Accept-Ranges`, Range одного диапазона → 206, за концом файла → 416; `private, no-store`, `nosniff`.
- Журнал: каждое прослушивание — «История действий», действие `listen` («Прослушивание записи»): пишется, если у этого
  пользователя по этому звонку нет записи за последние 10 минут (перемотка не плодит строк, обойти журнал, пропустив
  начало файла, нельзя).
- Доступ к файлам: production — ACL `u:espocrm:rx` и default ACL на `/var/spool/asterisk/monitor` (каталог `750`, файлы
  `644`) и ACL только прохода `u:espocrm:--x` на родителе `/var/spool/asterisk` (`asterisk:root 0750`, проверено только
  чтением 2026-10-17), не членство в группе asterisk — роль Ansible `espocrm` (этап 09, `deploy.md` §6); стенд — ACL
  `/var/lib/itvolga-espo/telephony/monitor`.

## 8. Слушатель (D-166)

`itvolga-telephony-listen` (systemd, пользователь EspoCRM): вход → `CoreShowChannels` → сверка → события (ответ на
действие и события, пришедшие в том же чтении, разбирает `Core/Ami/Inbox` — ничего не теряется). Раз в 15 с
отметка «видели» у идущих звонков и перечитывание настроек (запасной номер из админки действует со следующего звонка), раз в 30 с `Ping` (90 с без данных — выход), раз в 10 мин повторная сверка (закрывает
звонки без событий дольше 60 с, если каналов нет), раз в час очистка карточек (сутки) и запросов (30 дней). Любой сбой AMI
или БД — выход с кодом (69 АТС, 75 повтор, 78 не настроено — systemd не перезапускает), новый процесс сверяет звонки:
пропавший звонок закрывается как `lost` со временем «последний раз видели», идущий — подхватывается с текущими плечами
(кто звонил и кто ответил — по карточкам `TelephonyCard`, пара разговора — по каналам; ответ мобильного при переливе не
считается ответом телефона), неизвестный идущий — восстанавливается по каналам (время — по длительности каналов;
телефон, набравший внутренний номер, — внутренний звонок; номер исходящего — из данных `Dial`). Карточки и запросы звонков из CRM, которых нет ни на АТС, ни в памяти слушателя
(попытка закончилась, пока слушатель не работал, до создания `Call`), сверка закрывает (`closed`, запрос — `unanswered`;
только не менявшиеся 30 с). Выключение интеграции (`{"enabled": false}`) останавливает работающий слушатель при
следующем перечитывании настроек (до 15 с, код 78, systemd не перезапускает). Журнал приложения в слушателе
заглушён; состояние без номеров — `data/itvolga-telephony-status.json` (`task telephony:status`, `task stand:health`).
Повторный запуск не создаёт второй `Call` (уникальный ключ); удалённый администратором не восстанавливается.

## 10. Тестовая АТС стенда (D-172)

`task telephony:up | down | status`, `deploy/telephony/`: три контейнера одного образа (Ubuntu 26.04 по digest + пакет
Asterisk production + socat) во внутренней сети Docker без выхода наружу и без опубликованных портов:

- `pbx` — проверяемая АТС: структура диалплана production (`call-out`/`call-in`, `phones-local`, `phones-out` с теми же
  шаблонами, `incoming-menu`, поочерёдный обзвон с переливом на мобильный, `sub-monitor`, `sub-ifrussia`), AMI на
  127.0.0.1 с файлом пользователей из шаблона production; socat отдаёт AMI в сокет `/run/itvolga-espo-telephony/ami.sock`
  (группа `espocrm`). Соответствие номеров: 105 → 111, 100 → 112, 110 → 113, 108 → 118, 208 → 218, 106 → 116, 206 → 216,
  107 → 117; запасной номер стенда — 119; второй маршрут `sub-ifrussia` — `trunk-nedost`.
- `phones` — регистрирующиеся «настольные телефоны» (ответ/занято/не отвечает по AstDB `phone/<номер>`, звонок с
  телефона — `Local/<номер>*<куда>@desk`);
- `pstn` — «провайдеры» (поведение по AstDB `pstn/<номер>`, запоминает маршрут и номер последнего исходящего; входящий —
  `Local/<кто>*<линия>@call-pbx`).

Импорт (`task import:run`) и его тесты проверяют «тишину» по строкам всей базы стенда: на это время телефонию стенда
выключать (`task telephony:down`) — слушатель раз в час чистит старые карточки.

Опущено (не влияет на интеграцию): тренажёр, факс, ящик сообщений и конференция (ответ и отбой), проверки SHELL,
jitter buffer, постобработка записи. Синтетические номера — блок `+7 999 …`; реальные пользователи стенда имеют номера
100–110, 205–208, тестовые — 111–119, 211–219. Служба слушателя на стенде не стартует при загрузке; backup, restore,
stop и uninstall стенда останавливают и возвращают её (`pause_writers`/`resume_writers`; `stand:start` запускает слушателя,
если тестовая АТС работает); `uninstall --purge` удаляет каталог записей только с меткой `.itvolga-espo-telephony`.

## 11. История CDR (этап 07.2)

Звонки, прошедшие мимо слушателя (история до интеграции, звонок при остановленном слушателе), даёт импорт истории
Asterisk (`task import:run`, `import.md` «История звонков», D-173…D-178): CDR MySQL и `Master.csv` снимка группируются
в звонки по `linkedid` (D-20, D-175) и пишутся по тому же ключу `cAsteriskLinkedId` операцией `callHistory`
(`CdrCallWriter`, опция `itvolgaTelephony`) — только те звонки, что записала бы живая интеграция (§3, D-174), с теми же
правилами ответственного, участников, команды и клиентов (`CallParties`).

- Звонок, уже записанный живой интеграцией (без `cCdrSource`), не дублируется и не перезаписывается (живые факты
  точнее CDR: `billsec` включает голосовое меню); удалённый администратором не восстанавливается.
- Звонок истории — `cCdrSource` = `mysql`/`csv`, `cLiveState = ended`; повтор импорта пишет только его факты и запись,
  правки пользователей остаются; исчезнувший из следующего снимка не удаляется.
- Запись привязывается, только если файл в корне записей имеет размер и sha256 запечатанной описи снимка и путь не хранит
  другой звонок (`RecordingFiles`); на стенде файлы копирует root-помощник, на production они уже в каталоге Asterisk.
  Воспроизведение — тот же плеер и те же права, что у живых звонков (§7).
- Звонки PBXManager остаются с `cConnectorCallId` (только чтение, D-10): ссылка коннектора не аудио.

## 12. Ограничения

- Звонок, начавшийся и закончившийся, пока слушатель не работал, в AMI не виден — его даёт импорт истории CDR (§11,
  при следующем снимке и прогоне импорта).
- Переводы звонка (attended/blind transfer), перехват и очереди отдельно не моделируются: «ответил» — первый ответ
  человека; плечи после перевода — общие правила.
- Время — часы слушателя; у звонков, закрытых как `lost`, конец точен до 15 с.
- Если звонок принял мобильный при переливе, ответственный — первый, у кого звонил телефон (Q-54).
- Карточки — опросом раз в 3 с из каждой вкладки (WebSocket не используется).
- Два администратора, одновременно назначающие один свободный внутренний номер разным пользователям, могут оба
  успеть (проверка без блокировки; ревью 2026-10-13, решение владельца — ограничение): такой номер в работе никому не
  принадлежит (звонки — следующему звонившему или запасному, звонок из CRM запрещён), `task stand:health` и
  `task telephony:status` показывают число общих номеров.
- Асинхронная неудача Originate (телефон не зарегистрирован) пользователю не сообщается: карточка «набор номера»
  закрывается.
